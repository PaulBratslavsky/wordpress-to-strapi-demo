For years every site we launched ran on a classic WordPress theme. That worked well until clients started asking for the same content in an app, on an in-store screen and in a weekly newsletter. This post explains why most of our new builds now use a headless CMS, and what we learned moving the first three client sites.

What "headless" means for a small business

A headless CMS stores your content and serves it through an API. The website, the app and everything else are separate front ends that read from it. You edit a product description once and it updates everywhere.

Fetching content is a single request

On the front end, loading every article with its cover image looks like this:

const res = await fetch('https://cms.example.com/api/articles?populate=cover');
const { data } = await res.json();
console.log(`${data.length} articles loaded`);
{{image:laptop-dashboard|The Voltline dashboard and the marketing site read from the same API, so a price change is made once.}}

What was harder than expected

  • Previews. Editors expect to see a page before it goes live, so we set up draft previews on day one.
  • Old URLs. Every migrated page needed a redirect from its old address.
  • Page-builder layouts. They don't move across automatically. We rebuilt them as reusable sections:
    • hero
    • feature grid
    • call to action

We stopped copying the same text into four different places. That alone paid for the project.
